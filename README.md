
# Hospital Appointment Booking System

A FastAPI-based hospital management backend for patient registration, doctor schedules, appointment booking, consultations, patient records, live queues, and real-time notifications.

## Features

### Authentication and Access Control
- JWT-based authentication.
- Role-based access for Admin, Doctor, and Patient.
- Active-account validation.
- Protected API endpoints.

### Doctors and Appointments
- Doctor and department management.
- Doctor schedules and appointment slot validation.
- Appointment booking and status management.
- Appointment check-in.
- Appointment history tracking.

### Consultation and Patient Records
- Consultation records.
- Diagnosis, prescription, advice, and follow-up information.
- Patient file uploads and downloads.
- Patient appointment history.

### Live Queue and Notifications
- Real-time doctor queue using WebSockets.
- Patient notification WebSocket.
- Call-next-patient workflow.
- Queue snapshot broadcasting.
- Connection cleanup for disconnected clients.

### Additional Capabilities
- Database migrations using Alembic.
- Email notifications, subject to SMTP configuration.
- Automated tests using pytest.

## Installation and Setup

### 1. Clone or extract the project

Open PowerShell in the project directory.

### 2. Create and activate a virtual environment

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

If PowerShell blocks script execution, use an approved execution-policy setting for your environment rather than disabling security protections globally.

### 3. Install dependencies

```powershell
python -m pip install -r requirements.txt
```

### 4. Configure environment variables

Copy `.env.example` to `.env` and configure the required settings.

Configure:
- MySQL connection details.
- JWT secret and token settings.
- Email/SMTP settings, if email notifications are required.
- Any other variables documented in `.env.example`.

Use strong secrets and keep `.env` out of version control.

### 5. Create the database

Create the database specified in your configured database connection string using MySQL.

The database name in the configuration and the database created in MySQL must match.

### 6. Apply database migrations

```powershell
alembic upgrade head
```

### 7. Configure initial administrator access

Use the project's supported administrator setup procedure. Do not commit administrator passwords, JWT secrets, or production credentials.

### 8. Start the application

```powershell
uvicorn app.main:app --reload
```

## API Documentation

When the server is running, open:

- Swagger UI: http://127.0.0.1:8000/docs
- ReDoc: http://127.0.0.1:8000/redoc

Authenticate through the login endpoint and use the access token for protected endpoints.

## WebSocket Endpoints

### Doctor Queue

```text
/ws/queue/{doctor_id}?token={ACCESS_TOKEN}
```

Provides the initial queue snapshot and real-time queue updates. Access is restricted to the appropriate Doctor or Admin account.

### Patient Notifications

```text
/ws/notifications?token={ACCESS_TOKEN}
```

Provides a connection confirmation and real-time notifications for the authenticated user.

Use a valid access token and an active account for WebSocket authentication.

## Database Migrations

Create a migration after changing database models:

```powershell
alembic revision --autogenerate -m "describe your changes"
```

Apply migrations:

```powershell
alembic upgrade head
```

Check the current migration:

```powershell
alembic current
```

Review autogenerated migrations before applying them to important databases.

## Configuration and Security

- Keep credentials and secret keys in `.env`.
- Never commit `.env`, access tokens, or passwords.
- Keep `.env.example` limited to placeholder values.
- Do not commit virtual environments, caches, or private patient uploads.
- Restrict access to patient records and uploaded files.
- Use HTTPS/WSS and appropriate secret management in production.
- Configure SMTP credentials before testing email delivery.
